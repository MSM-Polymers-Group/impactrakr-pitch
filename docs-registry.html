RegistryRegistryRegistry

A ImpacTrakr mantém seu próprio registro à prova de adulteração de cada lote rastreado, e decide separadamente onde — se em algum lugar — um resultado aprovado é enviado como crédito em um registry externo.ImpacTrakr keeps its own tamper-evident record of every tracked batch, and separately decides where — if anywhere — an approved outcome gets submitted as a credit on an external registry.ImpacTrakr mantiene su propio registro a prueba de manipulación de cada lote rastreado, y decide por separado dónde — si en algún lugar — un resultado aprobado se envía como crédito en un registry externo.

O registro internoThe internal recordEl registro interno

O histórico completo de cada MassID é um log de eventos append-only encadeado em hash (veja Modelo de segurança). Esse log é o registro interno permanente, independente de qualquer registry externo estar envolvido ou não.Every MassID's full history is an append-only, hash-chained event log (see Security model). That log is the permanent internal record, independent of whether any external registry is ever involved.El historial completo de cada MassID es un log de eventos append-only encadenado por hash (vea Modelo de seguridad). Ese log es el registro interno permanente, independiente de si algún registry externo llega a estar involucrado.

Registry como abstração plugávelRegistry as a pluggable abstractionRegistry como abstracción conectable

Externamente, a ImpacTrakr modela um Registry como um livro-razão de destino abstrato, atrás de uma única interface adaptadora. A plataforma é deliberadamente registry-agnóstica — um registry futuro (uma blockchain diferente, um esquema regional) se pluga sem tocar no resto do código de domínio.Externally, ImpacTrakr models a Registry as an abstract destination ledger behind a single adapter interface. The platform is deliberately registry-agnostic — a future registry (a different blockchain, a regional scheme) plugs in without touching the rest of the domain code.Externamente, ImpacTrakr modela un Registry como un libro mayor de destino abstracto, detrás de una única interfaz adaptadora. La plataforma es deliberadamente registry-agnóstica — un registry futuro (una blockchain distinta, un esquema regional) se conecta sin tocar el resto del código de dominio.

Cada entrada de registry é identificada por nome e versão, e é append-only: uma vez que um crédito foi emitido contra uma versão de registry, essa referência continua auditável exatamente contra aquela versão mesmo depois que uma versão seguinte a substitui para novos envios.Each registry entry is identified by name and version, and is append-only: once a credit has been issued against a given registry version, that reference stays auditable against exactly that version even after a later version supersedes it for new submissions.Cada entrada de registry se identifica por nombre y versión, y es append-only: una vez que se emitió un crédito contra una versión de registry dada, esa referencia sigue siendo auditable exactamente contra esa versión aunque una versión posterior la reemplace para nuevos envíos.

O que é enviado, e quandoWhat gets submitted, and whenQué se envía, y cuándo

Só registros que já carregam um veredito totalmente aprovado no pilar de regras que o registry de destino aceita são elegíveis para envio — veja Padrão para saber qual é esse pilar. Uma integração de registry é opt-in por organização; nada é enviado externamente por padrão.Only records that already carry a fully passed verdict on the rule pillar the target registry accepts are eligible for submission — see Standard for which pillar that is. A registry integration is opt-in per organization; nothing is pushed externally by default.Solo los registros que ya llevan un veredicto totalmente aprobado en el pilar de reglas que acepta el registry de destino son elegibles para el envío — vea Estándar para saber cuál es ese pilar. Una integración de registry es opt-in por organización; nada se envía externamente por defecto.
