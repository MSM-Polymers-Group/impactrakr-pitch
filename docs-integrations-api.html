  • Autenticação — chaves de API por organização pra clientes máquina/ERP, independente do caminho de login humano.Authentication — organization-scoped API keys for machine/ERP clients, independent of the human-user login path.Autenticación — claves de API por organización para clientes máquina/ERP, independiente del camino de login humano.
  • Versionamento — a versão da API faz parte da própria URI, sem um prefixo geral separado, então um salto de versão é explícito em toda chamada em vez de um header que um cliente pode esquecer silenciosamente.Versioning — the API version is part of the URI itself, with no separate blanket prefix, so a version bump is explicit in every call rather than a header a client can silently forget.Versionado — la versión de la API es parte de la propia URI, sin un prefijo general separado, así que un salto de versión es explícito en cada llamada en lugar de un header que un cliente puede olvidar silenciosamente.
  • Paginação — endpoints de listagem usam paginação por cursor em vez de offset/limit, o que continua correto mesmo com novos registros sendo escritos concorrentemente.Pagination — list endpoints use cursor-based pagination rather than offset/limit, which stays correct even as new records are written concurrently.Paginación — los endpoints de listado usan paginación por cursor en lugar de offset/limit, lo que se mantiene correcto incluso cuando se escriben nuevos registros de forma concurrente.
  • Erros — toda resposta de erro segue um envelope estruturado consistente com um trace ID, então uma conversa de suporte consegue apontar exatamente a request que falhou.Errors — every error response follows a consistent structured envelope with a trace ID, so a support conversation can pinpoint the exact request that failed.Errores — cada respuesta de error sigue un envelope estructurado consistente con un trace ID, así que una conversación de soporte puede identificar exactamente la request que falló.
