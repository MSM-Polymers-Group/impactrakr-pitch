O que está disponível hoje para clientes máquina, e o que ainda está no roadmap.What's available today for machine clients, and what's still on the roadmap.Qué está disponible hoy para clientes máquina, y qué sigue en el roadmap.

Disponível hojeAvailable todayDisponible hoy

  • Autenticação — chaves de API por organização para clientes máquina/ERP, independente do caminho de login humano. Envie a chave no header Authorization: ApiKey <sua-chave> (ou X-API-Key).Authentication — organization-scoped API keys for machine/ERP clients, independent of the human-user login path. Send the key in the Authorization: ApiKey <your-key> header (or X-API-Key).Autenticación — claves de API por organización para clientes máquina/ERP, independiente del camino de login humano. Envíe la clave en el header Authorization: ApiKey <su-clave> (o X-API-Key).
  • Versionamento — a versão da API faz parte da própria URI (/v1/...), sem um prefixo /api separado, então um salto de versão é explícito em toda chamada em vez de um header que um cliente pode esquecer silenciosamente.Versioning — the API version is part of the URI itself (/v1/...), with no separate /api prefix, so a version bump is explicit in every call rather than a header a client can silently forget.Versionado — la versión de la API es parte de la propia URI (/v1/...), sin un prefijo /api separado, así que un salto de versión es explícito en cada llamada en lugar de un header que un cliente puede olvidar silenciosamente.
  • Autorização por escopo — cada chamada exige um escopo específico do recurso (ex.: massids:write, participants:read), não só uma chave válida. Uma chave criada para um papel só de leitura recebe 403 ao tentar escrever, mesmo autenticada corretamente.Scope-based authorization — every call requires a resource-specific scope (e.g. massids:write, participants:read), not just a valid key. A key issued for a read-only role gets 403 on a write attempt, even though it authenticates fine.Autorización por alcance (scope) — cada llamada exige un alcance específico del recurso (ej.: massids:write, participants:read), no solo una clave válida. Una clave creada para un rol de solo lectura recibe 403 al intentar escribir, aunque se autentique correctamente.
  • Paginação — endpoints de listagem usam paginação por cursor bidirecional em vez de offset/limit, o que continua correto mesmo com novos registros sendo escritos concorrentemente.Pagination — list endpoints use bidirectional cursor pagination rather than offset/limit, which stays correct even as new records are written concurrently.Paginación — los endpoints de listado usan paginación por cursor bidireccional en lugar de offset/limit, lo que se mantiene correcto incluso cuando se escriben nuevos registros de forma concurrente.
  • Erros — toda resposta de erro segue um envelope estruturado consistente com um trace ID, então uma conversa de suporte consegue apontar exatamente a request que falhou.Errors — every error response follows a consistent structured envelope with a trace ID, so a support conversation can pinpoint the exact request that failed.Errores — cada respuesta de error sigue un envelope estructurado consistente con un trace ID, así que una conversación de soporte puede identificar exactamente la request que falló.

Toda chave de API herda os escopos do papel do usuário que a emitiu. Os cinco papéis existentes hoje:Every API key inherits the scopes of the user role that issued it. The five roles that exist today:Toda clave de API hereda los alcances del rol del usuario que la emitió. Los cinco roles que existen hoy:

ADMIN
Todos os escopos — inclusive administração de organização, usuários e chaves de API.Every scope — including organization, user, and API-key administration.Todos los alcances — incluyendo administración de organización, usuarios y claves de API.
MEMBER
Leitura e escrita no dia a dia operacional — participantes, endereços, MassIDs, registries, homologações, projetos — sem administração de conta.Read/write on day-to-day operations — participants, addresses, MassIDs, registries, homologations, projects — no account administration.Lectura y escritura en la operación diaria — participantes, direcciones, MassIDs, registries, homologaciones, proyectos — sin administración de cuenta.
VIEWER
Só leitura em toda a superfície operacional.Read-only across the entire operational surface.Solo lectura en toda la superficie operativa.
AUDITOR (externo)AUDITOR (external)AUDITOR (externo)
Leitura da superfície operacional de uma organização à qual foi concedido acesso, mais escrita restrita à trilha de auditoria (achados e atestações) — nunca escrita operacional. Veja Verificação externa.Read access to the operational surface of an organization it has been granted access to, plus write restricted to the audit trail (findings and attestations) — never operational writes. See External verification.Lectura de la superficie operativa de una organización a la que se le concedió acceso, más escritura restringida al rastro de auditoría (hallazgos y atestaciones) — nunca escritura operativa. Vea Verificación externa.
SYSTEM
Reservado para o próprio motor de validação (dMRV) — não é um papel que uma organização cliente recebe.Reserved for the validation engine (dMRV) itself — not a role a client organization is issued.Reservado para el propio motor de validación (dMRV) — no es un rol que se emita a una organización cliente.

Ainda não disponívelNot yet availableAún no disponible

  • Chave de idempotência — nenhum endpoint de escrita aceita hoje um deduplicationId (ou equivalente). Uma retentativa de rede após um timeout pode criar um registro duplicado; até isso existir, o cliente precisa de sua própria lógica de deduplicação antes de reenviar uma escrita.Idempotency key — no write endpoint accepts a deduplicationId (or equivalent) today. A network retry after a timeout can create a duplicate record; until this exists, the client needs its own deduplication logic before resending a write.Clave de idempotencia — ningún endpoint de escritura acepta hoy un deduplicationId (o equivalente). Un reintento de red tras un timeout puede crear un registro duplicado; hasta que esto exista, el cliente necesita su propia lógica de deduplicación antes de reenviar una escritura.
  • Rate limit geral — existe um limitador por minuto pronto internamente (por usuário ou por chave de API), mas hoje ele só está ligado num endpoint específico (anti-enumeração de organização), não na API como um todo.Blanket rate limiting — a per-minute limiter exists internally (by user or by API key), but today it's only wired into one specific endpoint (organization anti-enumeration), not the API as a whole.Rate limit general — existe un limitador por minuto listo internamente (por usuario o por clave de API), pero hoy solo está conectado en un endpoint específico (anti-enumeración de organización), no en la API como un todo.
