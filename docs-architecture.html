How it works

Data does not go anywhere external until it has passed internal validation. Here's the full path, end to end.

1. Ingestion

Today, the fastest and most common way to start a pilot is a structured Excel/CSV import — no engineering integration required. Organization-scoped API keys are available today for machine clients (see Integrations); direct ERP integration is the roadmapped default for scaled clients.

2. Validation engine

Every record runs against the rule set(s) pinned to its project — see Standard for how that governance works. Each rule fails as either a hard BLOCK (stops progression) or a FLAG (routed to human review, can proceed if overridden).

3. Persistence & audit trail

Validated records and every state change on them are written to PostgreSQL as an append-only, hash-chained event log, inside your organization's isolated tenant. See Security model for how isolation and tamper-evidence actually work.

4. Dashboards

Role-based dashboards read only from validated data — nothing on a dashboard bypasses validation.

5. Optional registry submission

Only pre-validated, approved records are ever submitted to an external credit registry, and only for organizations that have opted into that integration. See Registry.

The stack underneath

Compute
AWS ECS in private subnets, behind API Gateway with a VPC Link — app servers have no public IP
Infrastructure as code
Pulumi
CI/CD
GitHub Actions — every deploy runs automated verification before it's considered live
Secrets
Doppler — no plaintext secrets in the repo or CI logs

Every non-trivial architectural choice behind this stack is written down as an internal Architecture Decision Record — the practice that keeps "why does it work this way" from becoming folklore.
