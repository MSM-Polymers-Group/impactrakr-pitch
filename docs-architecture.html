Como funcionaHow it worksCómo funciona

Nenhum dado sai da plataforma antes de passar pela validação interna. Veja a seguir o caminho completo, ponta a ponta.Data does not go anywhere external until it has passed internal validation. Here's the full path, end to end.Ningún dato sale al exterior hasta pasar por la validación interna. Aquí está el camino completo, de punta a punta.

1. IngestãoIngestionIngesta

Hoje, o jeito mais rápido e comum de começar um piloto é uma importação estruturada de Excel/CSV — sem exigir integração de engenharia. Chaves de API por organização já estão disponíveis hoje para clientes máquina (veja Integrações); integração direta com ERP é o caminho padrão planejado no roadmap para clientes em escala.Today, the fastest and most common way to start a pilot is a structured Excel/CSV import — no engineering integration required. Organization-scoped API keys are available today for machine clients (see Integrations); direct ERP integration is the roadmapped default for scaled clients.Hoy, la forma más rápida y común de empezar un piloto es una importación estructurada de Excel/CSV — sin necesidad de integración de ingeniería. Las claves de API por organización ya están disponibles hoy para clientes máquina (vea Integraciones); la integración directa con ERP es el camino por defecto planeado en el roadmap para clientes a escala.

2. Motor de validaçãoValidation engineMotor de validación

Cada registro roda contra o(s) conjunto(s) de regras fixado(s) no seu projeto — veja Padrão para entender essa governança. Cada regra falha como um BLOCK (bloqueio, interrompe o progresso) ou um FLAG (sinalização, vai para revisão humana, pode prosseguir se liberada).Every record runs against the rule set(s) pinned to its project — see Standard for how that governance works. Each rule fails as either a hard BLOCK (stops progression) or a FLAG (routed to human review, can proceed if overridden).Cada registro se ejecuta contra el o los conjuntos de reglas fijados en su proyecto — vea Estándar para entender esa gobernanza. Cada regla falla como un BLOCK (bloqueo, detiene el progreso) o un FLAG (marca, va a revisión humana, puede continuar si se anula).

3. Persistência & trilha de auditoriaPersistence & audit trailPersistencia y rastro de auditoría

Registros validados e cada mudança de estado neles são gravados no PostgreSQL como um log de eventos append-only encadeado em hash, dentro do tenant isolado da sua organização. Veja Modelo de segurança para entender como o isolamento e a evidência de violação funcionam de fato.Validated records and every state change on them are written to PostgreSQL as an append-only, hash-chained event log, inside your organization's isolated tenant. See Security model for how isolation and tamper-evidence actually work.Los registros validados y cada cambio de estado sobre ellos se escriben en PostgreSQL como un log de eventos append-only encadenado por hash, dentro del tenant aislado de su organización. Vea Modelo de seguridad para entender cómo funcionan realmente el aislamiento y la evidencia de manipulación.

4. PainéisDashboardsPaneles

Painéis baseados em papel de acesso leem só dados validados — nada em um painel pula a validação.Role-based dashboards read only from validated data — nothing on a dashboard bypasses validation.Los paneles basados en roles leen solo datos validados — nada en un panel se salta la validación.

5. Envio opcional a um registryOptional registry submissionEnvío opcional a un registry

Só registros pré-validados e aprovados são enviados a um registry de crédito externo, e só para organizações que optaram por essa integração. Veja Registry.Only pre-validated, approved records are ever submitted to an external credit registry, and only for organizations that have opted into that integration. See Registry.Solo los registros pre-validados y aprobados se envían a un registry de crédito externo, y solo para organizaciones que optaron por esa integración. Vea Registry.
