Security model

For IT and security reviewers: how tenant isolation, authentication, and the audit trail are actually enforced — not just described.

Multi-tenant isolation

  • Every operational table carries an organization identifier and has PostgreSQL Row-Level Security enabled and forced — a policy requires the organization id to match on every query, including ones a developer forgot to filter manually.
  • The organization scope is set per request via a database session variable, inside the same transaction as the query — there's no code path where "forgetting to filter" leaks another tenant's rows.
  • Schema migrations run under a separate, narrowly-scoped role that is the only one allowed to bypass row-level security, and only for schema operations, never application traffic.

Authentication

Human users authenticate via AWS Cognito — password storage, sessions, and MFA (where enabled) are offloaded to AWS-managed infrastructure. Authorization (what an authenticated user can do) is self-hosted and role-based. Machine clients authenticate with organization-scoped API keys.

A written threat model

There's an explicit, documented threat model cataloguing who might attempt cross-tenant access (an unauthenticated attacker, an authenticated user probing another tenant's resource IDs, a tampered or stale token, an internal operator with direct database access) and which automated test must exist and stay green for each one. Example: a user from Organization B requesting Organization A's resource by ID must get a "not found," never a "forbidden" — a "forbidden" response would itself leak that the resource exists.

Data integrity

Two independent mechanisms protect the audit trail:

  • Hash-chained event log — every state change is an event whose hash is computed from its own content plus the previous event's hash. Editing or deleting a past event breaks every hash after it, so retroactive tampering is mathematically detectable.
  • Structured audit log — independently, every mutation is logged with a before/after diff, the acting user or API key, IP address, and a request ID.

Storage & database access

Compliance documents live in an S3 bucket with no public access and no presigned URLs — every download is streamed through an authenticated API call, so nothing survives a logout as a standalone link. The production database has no public endpoint at all; external access goes exclusively through an AWS Systems Manager port-forwarding tunnel.
